# Razorpay Setup Guide

Complete guide for setting up Razorpay payments in development and production.

---

## Step 1 — Create Razorpay Account

1. Go to [https://dashboard.razorpay.com](https://dashboard.razorpay.com)
2. Sign up with your business email
3. Complete KYC (required for live payments — optional for test mode)

---

## Step 2 — Get Test API Keys

1. Dashboard → Settings → API Keys → **Generate Test Key**
2. Copy: **Key ID** (starts with `rzp_test_`) and **Key Secret**
3. Add to `server/.env`:

```
RAZORPAY_KEY_ID=rzp_test_xxxxxxxxxx
RAZORPAY_KEY_SECRET=your_secret_here
```

---

## Step 3 — Set Up Webhook

1. Dashboard → Settings → Webhooks → **Add New Webhook**
2. **Webhook URL**: `https://your-domain.com/api/v1/payment/webhook`
   - For local dev: use ngrok (see Step 4 below)
3. **Secret**: create a strong random string (min 32 chars)
   - Add to `server/.env`: `RAZORPAY_WEBHOOK_SECRET=your_secret`
4. **Events to subscribe** — check ONLY these:
   - ✓ `payment.captured`
   - ✓ `payment.failed`
5. Click **Save**

> **IMPORTANT**: The `RAZORPAY_WEBHOOK_SECRET` is different from the `RAZORPAY_KEY_SECRET`.
> The webhook secret is set by YOU in the Razorpay dashboard.
> The key secret is generated by Razorpay when you create API keys.

---

## Step 4 — Local Development with ngrok (Webhook Testing)

Razorpay webhooks need a public URL — your `localhost` won't work.
Use ngrok to expose your local backend:

```bash
# Install ngrok
npm install -g ngrok

# Start your backend first
npm run dev  # (in server/)

# In a new terminal, expose port 5000
ngrok http 5000

# Copy the HTTPS URL from ngrok output:
# e.g. https://abc123.ngrok.io

# Update Razorpay webhook URL to:
# https://abc123.ngrok.io/api/v1/payment/webhook
```

ngrok also gives you a **web inspector** at [http://localhost:4040](http://localhost:4040)
to see all webhook requests — very useful for debugging.

> **NOTE**: ngrok URL changes every session unless you have a paid account.
> Update the webhook URL in Razorpay dashboard each time you restart ngrok.

## Step 5 — Test Cards (Test Mode Only)

| Card Number           | Network    | Result   |
|-----------------------|------------|----------|
| `4111 1111 1111 1111` | Visa       | Success  |
| `5267 3181 8797 5449` | Mastercard | Success  |
| `4000 0000 0000 0002` | Visa       | Declined |

- **CVV**: any 3 digits
- **Expiry**: any future date
- **OTP**: `1234` (Razorpay test OTP)

---

## Step 6 — Test UPI (Test Mode)

| UPI ID              | Result          |
|---------------------|-----------------|
| `success@razorpay`  | Always succeeds |
| `failure@razorpay`  | Always fails    |

---

## Step 7 — Going Live (Production)

1. Complete Razorpay KYC in dashboard
2. Generate **LIVE** API keys (starts with `rzp_live_`)
3. Replace test keys in production `.env` with live keys
4. Update webhook URL to production domain
5. Test one real payment of ₹1 to confirm everything works
6. Refund the ₹1 test payment from Razorpay dashboard

## Common Issues and Fixes

### "Razorpay is not defined" error
The Razorpay `checkout.js` script failed to load. Check internet connection. The script loads lazily on first payment attempt.

### Webhook signature invalid in local dev
Make sure you're using the `WEBHOOK_SECRET` from your Razorpay dashboard, **not** the `KEY_SECRET`. They are different values.

### Raw body undefined in webhook handler
Make sure `express.json()` is **NOT** applied to the webhook route. Check your `app.ts` middleware order. The webhook route uses `express.json({ verify })` to preserve the raw body for signature verification.

### Email not sending (Gmail)
Gmail requires an **App Password** (not your regular password) when 2FA is enabled:
1. Google Account → Security → 2-Step Verification → App Passwords
2. Select "Mail" and "Other (custom)" → Generate
3. Use the 16-char password in `SMTP_PASS` (no spaces)

### Webhook not receiving in local dev
ngrok URL changes on each restart. Update the webhook URL in Razorpay dashboard every time you restart ngrok.

### Payment captured but emailSent stays false
Check backend logs for SMTP errors. The payment is already captured safely — email failure does not affect payment. Fix SMTP credentials and use "Resend Thank You Email" button in admin.

### Duplicate payments in MongoDB
The idempotency middleware prevents duplicate orders within 1 minute per IP+email+amount. If duplicates appear, check Redis connection — the middleware falls through if Redis is unavailable.
